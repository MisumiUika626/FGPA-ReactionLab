# ReactionLab 项目设计

> 本科《数字电子技术 B》课程设计。基础功能优先，扩展功能不影响验收。
> 本文规定需求、模块职责及硬件配置；公共信号与时序以 `interfaces.md` 为准。

## 1. 基础功能

| 编号 | 功能 | 实现要求 |
| --- | --- | --- |
| F01 | 初始化 | Clear 返回测试模式，显示 000，LED 熄灭，保留历史记录 |
| F02 | 开始测试 | Start 后数码管全灭，进入等待状态 |
| F03 | 随机刺激 | 等待 1～6 s 后点亮 LED；最小版本可先使用固定延时 |
| F04 | 反应计时 | 从 LED 点亮时开始，每满 1 ms 加 1，实时显示三位十进制数 |
| F05 | 停止计时 | Stop 锁定反应时间并保存一次有效成绩 |
| F06 | 犯规检测 | LED 点亮前按 Stop，显示 Err，不保存成绩 |
| F07 | 超时保护 | 达到 999 ms 自动停止并显示 999，不保存成绩 |
| F08 | 历史记录 | 保存最近 10 次有效成绩，写满后覆盖最旧记录，支持逐条查询 |
| F09 | 数据统计 | 查询全局复位以来有效成绩的最小值与最大值 |
| F10 | 模式切换 | 支持 TEST、HISTORY、MIN、MAX；等待及计时期间禁止切换 |

F01～F09 对应课程要求及其具体实现约定；F10 为实现查询所采用的交互方案。
全局复位清空历史与统计。正常结束、犯规及超时后，按 Clear 开始准备下一轮。

## 2. 可选扩展

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P1 | 平均反应时间 | 查询最近 10 条有效成绩的整数平均值；无记录显示横线 |
| P2 | 反应速度评级 | 按反应时间区间给出游戏化等级，具体阈值与显示方式另定 |
| P3 | 双人竞技 | 两人共享刺激，分别锁存成绩并判断胜负；硬件允许时考虑 |

基础功能全部通过测试后，由双方确认是否实现扩展；必要时同步修订接口。
不引入 UART、上位机、服务器等非必要功能。

## 3. 系统架构与分工

```text
                         top.v（A）
                              │
              ┌───────────────┴───────────────┐
        reaction_core（A）       reaction_peripheral（B）
        状态机、随机延时          按键同步、消抖、模式控制
        反应计时、犯规、超时      历史存储、统计、显示
              │                              │
          刺激 LED                        数码管
```

B 向 A 发送按键事件，A 向 B 返回状态、计时值与保存事件；双方共享时钟和复位。
B 负责显示驱动，A 负责顶层连接、板级适配及 Quartus 工程。内部模块按需拆分。
双方各自编写 Testbench 与报告对应部分，集成、硬件测试及答辩共同完成。

## 4. 硬件与开发环境

| 项目 | 配置 |
| --- | --- |
| FPGA | Cyclone IV E，EP4CE6E22C8 |
| HDL / EDA | Verilog-2001 / Quartus Prime Lite 18.1.0 / ModelSim Intel FPGA Starter |
| 开发环境 | WSL 或 Windows；Windows 执行 EDA 仿真、综合和烧录 |
| 时钟频率 | TBD；50 MHz 仅为开发默认值，以实际硬件为准 |
| 按键 | 逻辑需求 Start、Stop、Clear、Mode；实际数量及极性 TBD |
| 显示 | 逻辑需求三位七段数码管；实际段线、位选、扫描方式及极性 TBD |
| LED / 复位 / 引脚 | 刺激 LED、模式提示资源、复位来源、I/O 标准及引脚分配 TBD |

未确认硬件参数不得用于实际烧录；按键或显示资源不足时，双方先确认适配方案。
计时与随机等待参数化，仿真可使用缩短的时基；硬件编译使用已确认的真实参数。

## 5. 测试与验收

| 类别 | 最低验收标准 |
| --- | --- |
| Core | 正常计时、随机等待范围、犯规、999 ms 超时、Clear 及同沿冲突符合接口规范 |
| Peripheral | 按键单次触发、历史写入和覆盖、空记录、最大最小值、模式隔离及显示正确 |
| 集成 | 完整测试与查询流程正确；每次有效测试仅保存一次；复位与 Clear 行为正确 |
| 硬件 | Quartus 编译通过，实际烧录后逐项演示基础功能；已启用扩展也须验证 |
| 报告 | 分工、设计用时、总体方案、顶层 RTL 图、状态图与编码/转换/输出表、仿真及分析、引脚表、运行照片、心得、带注释源码 |

保留真实测试结果；未执行的测试标记 NOT RUN，不得编造数据。
开发顺序：最小可运行系统 → 完整基础功能 → 可选扩展 → 硬件测试与报告。
